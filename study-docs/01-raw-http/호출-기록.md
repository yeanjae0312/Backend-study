# 호출 기록: Phase 1 완료 체크표

Phase 1의 마지막 항목. 모든 엔드포인트를 한 번씩 직접 호출하고, 눈으로 확인한 것을 표에 적는다. 목적은 두 가지다. 첫째, 상태 코드와 헤더를 "안다"가 아니라 "봤다"로 만드는 것. 둘째, Phase 2에서 Nest로 같은 API를 만들 때 **이 표가 그대로 수락 기준**이 된다. 같은 요청에 같은 응답이 나오면 이식이 끝난 것이다.

기록 방법: `requests.http`에서 요청을 보내고, 응답 패널에서 확인한 뒤 표의 "확인" 칸에 날짜를 적는다. 응답을 파일로 남기고 싶으면 응답 패널에서 `Ctrl+S`(REST Client의 Save Response).

---

## 1. 메모 API

| # | 요청 | 기대 상태 | 확인할 헤더·바디 | requests.http | 확인 |
|---|---|---|---|---|---|
| 1 | `GET /notes` (비어 있을 때) | 200 | `content-type: application/json; charset=utf-8`, 바디 `[]`, `content-length: 2` | 1 | |
| 2 | `POST /notes` 정상 JSON | 201 | 바디에 `id`(UUID), `createdAt`(ISO). `content-length`가 글자 수보다 큼(한글) | 2 | |
| 3 | `POST /notes` 깨진 JSON | 400 | 바디 `{"error":"body is not valid JSON"}` | 3 | |
| 4 | `POST /notes` 타입 틀림 | 400 | 바디 `{"error":"title and content must be strings"}` | 4 | |
| 5 | `POST /notes` 빈 바디 | 400 | `readJson`이 `undefined`를 주고 `isNoteInput`이 거른다 | (직접 추가) | |
| 6 | `PUT /notes` | 405 | `allow: GET, POST` | 5 | |
| 7 | `GET /notes/:id` 있는 id | 200 | 2번에서 만든 것과 같은 객체 | 6 | |
| 8 | `GET /notes/:id` 없는 id | 404 | 바디 `{"error":"note not found"}` | 7 | |
| 9 | `PUT /notes/:id` | 405 | `allow: GET, DELETE` | (직접 추가) | |
| 10 | `DELETE /notes/:id` | 204 | **바디 없음**, `content-length` 없음 | 8 | |
| 11 | `DELETE /notes/:id` 두 번째 | 404 | 멱등성: 두 번째는 404지만 서버 상태는 같다 | 8 다시 | |
| 12 | `GET /anything` | 404 | 바디 `{"error":"not found"}` | 9 | |
| 13 | `GET /notes?page=2` | 200 | 쿼리는 무시되고 목록이 온다. `pathname`만 보기 때문 | (직접 추가) | |

5, 9, 13번은 requests.http에 없다. 직접 추가한다. 요청 하나를 스스로 써 보는 것도 기록의 일부다.

## 3. CORS (CORS.md 끝낸 뒤)

| # | 요청 | 기대 | 확인할 것 | 어디서 | 확인 |
|---|---|---|---|---|---|
| 19 | 5500 페이지에서 `GET /notes`, 헤더 없이 | 콘솔 CORS 에러 | 서버 로그에는 `GET /notes` 찍힘. Network 탭 상태 200 | 브라우저 | |
| 20 | `allow-origin` 추가 후 `GET /notes` | 200 | 응답 헤더에 `access-control-allow-origin` | 브라우저 | |
| 21 | `POST /notes` JSON | OPTIONS 204 → POST 201 | Network 탭에 요청 두 개. OPTIONS 응답의 allow-methods, allow-headers | 브라우저 | |
| 22 | `OPTIONS /notes` | 204 | 바디 없음. 브라우저 없이도 응답은 된다(의미는 없다) | requests.http (직접 추가) | |
| 23 | `/visits` `credentials: "include"` | 200, 숫자 증가 | 요청 헤더에 `cookie`, 응답에 `access-control-allow-credentials: true` | 브라우저 | |
| 24 | `allow-origin: *` + credentials | 콘솔 에러 | 에러 메시지 전문을 읽는다 | 브라우저 | |
| 25 | REST Client로 `GET /notes` + `Origin: http://evil.com` | 200 | CORS 헤더가 5500 값으로 오지만 **응답은 온다**. 브라우저가 아니면 CORS는 없다 | requests.http (직접 추가) | |

## 5. 서버 종료와 에러

| # | 상황 | 기대 | 확인할 것 | 확인 |
|---|---|---|---|---|
| 29 | Ctrl+C | `shutting down` 로그 후 종료 | 진행 중 요청이 있으면 끝낸 뒤 종료 | |
| 30 | 핸들러에 `throw new Error("boom")`을 넣고 호출 | 500 | 바디 `{"error":"internal server error"}`. 스택은 터미널에만. **프로세스가 안 죽는다** | |
| 31 | `send` 안에서 `content-length` 줄을 지우고 `GET /notes` | 200 | 응답 헤더에 `transfer-encoding: chunked`. Content-Length 없으면 Node가 chunked로 바꾼다 | |

30, 31번은 코드를 바꿨다 되돌리는 실험이다. 끝나면 `node check.ts`가 `ok`인지 본다.
